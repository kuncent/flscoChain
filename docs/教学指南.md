# 绿色低碳联盟链实训平台 · 教学指南

> 适用对象：授课教师与参训学生。
> 本文档基于平台代码调研编写（backend/app/routers/ 与 frontend/src/views/），引用的端点与页面名均以代码为准；代码中未实现的内容会明确标注"待确认"。
> 业务主线：搭建一条绿色低碳联盟链，6 大联盟成员围绕"低碳行为 → 发放绿色能量 → 兑换绿色资产"开展运营。

### ① 搭链教程：10 步与组织节点矩阵

教程步骤（`chain.py` TUTORIAL）：

| 步骤 | 标题（摘要） |
|---|---|
| 1 | 下载官方脚本并生成 4 节点联盟链（证书体系建立） |
| 2 | 检查节点进程与证书目录（联盟准入凭证核验） |
| 3 | 检查日志出块（PBFT 共识确认 + 日志分析） |
| 4 | 接入控制台（SDK 证书配置 + 链状态查询） |
| 5 | 联盟组织证书与节点归属核查 |
| 6 | 6 组织治理规则公示（能量发放规则表） |
| 7 | 注册 6 组织钱包（链上身份登记 + 钱包激活验证） |
| 8 | 联盟上线健康检查（节点 + 证书 + 三合约探针） |
| 9 | 部署 GreenEnergy 绿色能量代币 |
| 10 | 商业化全链路验证（5 业务角色发放 → 居民持有 + 交易确认） |

组织节点矩阵（教程内反复强调的映射关系）：

```
node0 = 🛡️管理员 + 🚇地铁集团     node1 = 🚌公交集团 + 🚲共享单车
node2 = 📦外卖平台 + ♻️回收公司    node3 = 🔥热备共识（可扩展监管审计）
```

每步内置命令序列（`commands`）、预期输出（`expected`）与故障排查提示（`tip`），学生在搭链云桌面逐条执行即可。

### ② 六联盟角色与能量规则（`eco.py` ROLES）

| 角色 | key | 钱包 | 能量规则 | 其他权限 |
|---|---|---|---|---|
| 管理员 | admin | 0xadmin | 不发能量（治理角色，避免利益冲突） | 部署合约、管理树种、发放植树证书 |
| 地铁集团 | metro | 0xmetro | 乘坐地铁 ≥10km → +50 | 可发勋章 |
| 公交集团 | bus | 0xbus | 乘坐公交 ≥5min → +20 | 可发勋章 |
| 共享单车 | bike | 0xbike | 骑行 ≥2km → +15 | 可发勋章；**骑行券仅 bike 可发放** |
| 外卖平台 | takeout | 0xtakeout | 绿色外卖（无需餐具）→ +10 | 可发勋章 |
| 回收公司 | recycling | 0xrecycle | 回收 ≥1kg → +100 | 可发勋章 |

内置三合约：GreenEnergy（ERC20 能量代币）、PlantCertificate（ERC721 植树证书）、EcoBadge（ERC1155 勋章 / 骑行券）。默认勋章类型：生态勋章（10 能量）、骑行券（20 能量，仅 bike 发放）。

### ③ 合约安全审计说明

`POST /api/contracts/audit` 对 Solidity 源码做静态检查（重入攻击、缺事件、缺访问控制、Gas 优化等），返回问题清单（含问题行号与修复建议）与评分（`score = 100 − 高危×20 − 中危×10 − 低危×5`）。平台内置"漏洞修复关卡"：`contracts/bugs/ReentrantVault.sol`（重入漏洞）与 `contracts/bugs/PhishingAuth.sol`（tx.origin 鉴权缺陷）两份关卡合约，可经 `GET /api/contracts/builtin`（合约 IDE 内置工程）获取源码 → 调用 `POST /api/contracts/audit` 检出漏洞（返回行号 + 修复建议）→ 学生修改源码修复漏洞 → 重新审计至高危项清零（高危清零计为一次"审计通过"，累计 2 次通过解锁成就"编程关卡通关" curriculum_l5，`achievements.py`）。`POST /api/contracts/audit` 每次调用会写入 `contract_audit` 埋点，累计 5 次可解锁成就"安全审计员"。实训报告中"进入合约安全 CTF 挑战 Reentrancy 漏洞"为进阶建议文案（`report.py`），对应独立挑战系统待确认。

### ④ 商业逻辑三道防线

1. **业务单号防刷**：发放能量必须携带业务单号（地铁/公交 `trip_no`、单车/外卖 `order_id`、回收 `order_no`）；同一 `proof_no + role_key` 重复发放会命中 UNIQUE 索引 `idx_energy_proof_role`，接口幂等返回旧结果并提示"该业务单号已发放过能量"。
2. **凭证对账**：每笔发放记录写入 `eco_energy_records`，含发放方钱包、业务单号、凭证 JSON 原文、是否通过校验（`proof_validated`）、校验阈值（如 `distance_km ≥ 10 km`）；教师用 `GET /api/eco/errors/list` 汇总全班操作日志对账。
3. **成绩闭环**：平台行为数据自动计算实训成绩 → 教师录入评分 → 合成综合成绩，详见下节。

## 二、教师使用流程

### 成绩体系说明（`grades.py`）

三段式成绩：

- **实训成绩**（training_score）：平台按钱包的真实行为数据自动计算，**教师不可直接修改**；
- **教师评分**（score）：教师手动录入（实训报告 / 课堂表现，0–100）；
- **综合成绩**（final_score）：系统合成 = **实训成绩 × 60% + 教师评分 × 40%**。

实训成绩 4 维权重（合计 100%）：

| 维度 | 权重 | 计分指标（每项有封顶） |
|---|---|---|
| 链搭建 chain_setup | 20% | IDE 打开内置工程、保存工程次数 |
| 合约开发 contract_dev | 30% | 编译成功次数、已部署合约数 |
| 链上验证 chain_verify | 25% | 接口调用、合约调用、链上交易笔数 |
| 联盟治理 alliance_gov | 25% | 角色切换、能量发放（接收方）、NFT 铸造/交易、ERC20 转账、报告查看 |

权限：仅教师（roleId=3）与管理员（roleId=1）可访问成绩接口；教师查询时默认只返回自己班级的数据。

### 操作步骤

1. **录入成绩**
   - 进入"学生成绩"页 `/grades`（教师专属菜单），按 学号 + 课程 唯一提交 `POST /api/grades/upsert`；
   - 提交时**务必填写学生的链上钱包地址（wallet）**，系统会自动计算并写入实训成绩与综合成绩；
   - 如需预览某钱包的实时得分明细，可调用 `POST /api/grades/compute-training`（只算不入库）。
2. **刷新实训分**
   - 学生活动数据持续累积后，调用 `POST /api/grades/refresh-training` 一键批量重算所有已绑定钱包记录的实训成绩与综合成绩（前端入口在 `/grades` 页面，具体按钮位置以页面为准）。
3. **查看班级看板与搭链进度**
   - 总览页 `/dashboard` 教师视角自动展示"班级实训进度看板"（数据来自 `GET /api/auth/platform-progress`）：班级人数、平均完成步数（x/10）、平均进度、平均实训成绩、每一步的班级完成率柱状条、学生明细（姓名/学号、完成进度、实训成绩、综合成绩）；
   - 学生成绩页 `/grades` 提供"班级搭链进度看板"（数据来自 `GET /api/chain/tutorial/progress/class`，仅教师/管理员可见）：每位学生的搭链完成步数（x/10）、卡点步骤（首个未完成步骤）与平均步骤耗时，便于课堂集中讲解共性卡点；
   - 班级学生名单与各自进度概要可用 `GET /api/auth/class-students` 查询；
   - 按课程聚合统计用 `GET /api/grades/stats`；生态模块操作日志汇总用 `GET /api/eco/errors/list`。
4. **成绩草稿（自动闭环）**
   - 学生在"实训报告"页 `/report` 生成报告时会触发 `POST /api/grades/auto-draft`：该钱包完成 10 步搭链后自动创建"区块链实训"成绩草稿（教师评分默认 0，待教师录入），教师后续只需补录评分。

## 三、学生学习路径建议（总览页 `/dashboard` 学习路径模块）

学习路径按 4 阶段、10 个节点组织，每个节点含 学习目标 / 知识锚点 / 验收条件：

| 阶段 | 节点（页面） | 建议用时 | 验收要点 |
|---|---|---|---|
| **P1 链底层** | ① 总览 `/dashboard`（起点） | 5 分钟 | 能复述业务架构：谁发能量、谁兑换、能量如何流转 |
| | ② 搭链云桌面 `/cloud`：10 步搭链（必修） | 30 分钟 | 10/10 步完成、部署 GreenEnergy、完成 6 角色发能量链路验证 |
| **P2 合约开发** | ③ 合约 IDE `/ide` | 15 分钟 | 查看 3 份内置合约源码、编译 ≥1 次、部署 PlantCertificate 或 EcoBadge |
| | ④ 合约管理 `/contracts` | 5 分钟 | 3/3 合约全部部署，能区分 ERC20/721/1155 用途 |
| | ⑤ 接口调试 `/interfaces` | 10 分钟 | 成功调用 ≥1 个 view 方法 + ≥1 个写方法上链 |
| **P3 联盟运营（核心）** | ⑥ 绿色低碳联盟链 `/eco` | 40 分钟 | 6/6 角色切换体验、≥3 种角色发能量、兑换 ≥2 类资产 |
| | ⑦ ERC20 钱包 `/wallet` | 5 分钟 | 查询能量余额，理解"发放→累积→消耗"流转 |
| | ⑧ NFT 交易市场 `/nft` | 10 分钟 | 铸造 ≥1 件 NFT，理解证书/勋章的 NFT 本质 |
| **P4 链上验证** | ⑨ 调用监听器 `/monitor` | 5 分钟 | 找到自己的 mint/transfer 调用，理解 status=1/0 |
| | ⑩ 区块链浏览器 `/explorer` | 5 分钟 | 按 tx_hash 查交易并解码 Transfer 事件 |

**L5 联盟运营微任务（搭链 10/10 完成后，"今日任务"自动切换为 10 个微任务）**：

- Phase 1 系统激活（T1–T2）：管理员激活 3 份系统合约；依次体验 6 大角色；
- Phase 2 能量发放（T3–T7）：依次切换地铁/公交/单车/外卖/回收 5 种角色发放能量；
- Phase 3 资产兑换（T8–T10）：兑换 ≥2 种树种的植树证书、勋章 + 骑行券，最后在 `/report` 生成实训报告查看评分。

建议节奏：先按 P1→P4 主线走完（约 2 课时），L5 微任务可作为第 3 课时的课堂实操与抽查依据（完成状态以服务端自动验收为准：`GET /api/missions/curriculum` 按钱包核对平台真实业务数据，界面标注"服务端验收"或"本地打卡"来源，未达标时本地打卡仅作降级记录）。

**成就激励**：成就中心 `/achievements` 展示 15 个成就（如"初次编译""部署专家""安全审计员"，新增"联盟全能角色" role_all_six、"审计初体验" audit_first、"编程关卡通关" curriculum_l5）与 3 个挑战任务（每日编译、Gas 挑战、生态链挑战）；进度由服务端按真实行为数据核算，学生无法伪造，可作为课堂积分制参考。

## 四、角色运营剧本示例："绿色出行日"（约 1 课时）

**场景**：地铁集团、共享单车作为联盟成员发放绿色能量，居民（学生本人钱包）骑行出行并兑换奖励，审计方（教师或轮值学生）事后对账。
**课前检查**：GreenEnergy / PlantCertificate / EcoBadge 三合约已部署（`GET /api/eco/contracts/status`，未部署时在 `/eco` 页一键部署 `POST /api/eco/contracts/deploy`）。

| # | 步骤 | 操作者 | 页面 / 端点 | 预期结果 |
|---|---|---|---|---|
| 0 | 学生登录并确认钱包 | 学生 | 登录后进入总览 `/dashboard` | 顶栏显示本人钱包地址 |
| 1 | 地铁集团选角色 | 地铁组学生 | `/eco` 页切换角色（`POST /api/eco/role/select`，role_key=metro） | 角色卡片显示"地铁集团" |
| 2 | 发放出行凭证能量 | 地铁组学生 | `/eco` 页能量发放表单（`POST /api/eco/energy/issue`）：接收方=学生钱包，凭证填 trip_no、进站口、出站口、进站时间、distance_km=12 | 学生 +50 能量；返回业务单号 proof_no 与链上 tx_hash |
| 2b | 防刷演示（可选） | 地铁组学生 | 用**同一个 trip_no** 重复提交 | 返回 `idempotent: true` 与提示"该业务单号已发放过能量"，余额不变 |
| 3 | 骑行发放 + 骑行券 | 单车组学生 | 切换 bike 角色：`POST /api/eco/energy/issue`（凭证 order_id、distance_km=3.2）→ +15；再 `POST /api/eco/badges/mint`（type_id=骑行券类型）向学生发放骑行券 | 学生 +15 能量并收到骑行券（ERC1155） |
| 4 | 学生兑换奖励 | 学生（切回本人角色） | `/eco` 页兑换区：`POST /api/eco/badges/exchange`（badge_type=badge，生态勋章 10 能量）；能量充足时兑换植树证书 `POST /api/eco/certificates/exchange` | 能量扣减转至管理员国库，获得勋章/证书 NFT |
| 5 | 余额与资产核对 | 学生 | `/wallet` 页查 GreenEnergy 余额与转账记录；`GET /api/eco/wallet/{wallet}` 综合查询角色、能量、证书、勋章、骑行券 | 账实一致 |
| 6 | 审计方对账 | 教师/轮值学生 | `GET /api/eco/energy/records?wallet=…`（逐笔核对 proof_no、proof_validated、proof_threshold）；`GET /api/eco/errors/list`（全班操作日志与 error/warn/success 统计）；`/monitor` 页看调用分布；`/explorer` 页按 tx_hash 验证上链 | 每笔能量可追溯到"业务单号 → 凭证原文 → 链上交易" |
| 7 | （可选）市场流通 | 任意学生 | `POST /api/eco/market/list` 挂牌资产 → 另一学生 `POST /api/eco/market/buy` 用能量购买 | 体会绿色资产二级市场 |

**课堂讲解要点**：
- 权限闭环：发放前操作者必须先切换到对应联盟角色，否则接口返回 403（模拟真实联盟"持证准入"）；
- force 参数：`POST /api/eco/energy/issue` 支持 `force=true` 跳过凭证校验，仅供教师演示，记录会标记 `proof_validated=0`，审计对账时可借此讲解"绕过校验的痕迹"；
- 能量回收：兑换时能量 `transfer` 至管理员国库，与低碳行为发放形成闭环。

## 六、近期 API 契约变更说明

> 以下变更影响旧版前端 / 外部脚本的兼容性，集成方需同步调整。

- `POST /api/auth/encrypt`：原 `GET`（密码拼在 URL）改为 `POST` 接收密码（放请求体，不落盘 / 不记录日志）；
- `GET /api/auth/session`：改为对 `Authorization: Bearer <JWT>` 的平台自签 JWT 验签（24h 有效），前端登录后需保存并在后续请求中携带；
- 全站接口不再信任前端自报的 `X-*` 身份头（X-Wallet / X-User-Id / X-User-Name 等），身份统一由 JWT 验签解析（`app/security.py`），旧脚本仅靠自报头调用会被拒绝或拿到匿名视角数据；
- `GET /api/achievements/my` 与 `GET /api/achievements/challenges/my`：响应结构由 `{items, stats}` 变为直接返回数组（字段对齐 AchievementBadge 组件）。
