1.1三条判断

  1. 平台的"真链、真评分"是可信的，但"看得见"是不可信的。 学生 0xlearner 实际有 19 份已部署合约、13 次角色切换（实时重算 88.8 分），但个人报告的链上交易笔数恒为 0（P0-3）， 同一份数据在成绩册显示 84.3、在个人报告显示 43、在全局报告显示 80（P1-7 / P2-10）。 教学产品里，"学生不信任分数"比"没有分数"破坏性更大——建议把 P0-2 / P0-3 / P1-7 作为同一个专项一起修，而不是拆成三条各修一半。
  2. 教师侧最痛的不是缺功能，而是"看不到本班 + 改不动范围"。 班级归属为空导致三块看板恒空（P0-1），但同一份数据在成绩列表又是"全校不过滤"； 而一键刷新（P1-18）、删除成绩（P1-19）、跨教师覆盖（P2-20）三个写动作都不受班级与录入人约束。 读不到 scope、写不限 scope，是同一个缺失的两面：平台没有贯穿读写的"教学作用域（班级 / 学校 / 录入教师）"。
  3. 界面把"演示态"当"真实态"呈现，教师会照它讲错。 侧边栏"整体学习进度"是固定值（P1-5）、登录页区块流是动画（P2-12）、云桌面 1–5 步是仿真（P2-11）、 引擎切换按钮点了没有后端接口却提示成功（P1-17）、平均 Gas 恒为 0（P3-15）。 建议统一一条产品规范：凡是与链上真实状态无关的展示，必须带"演示"标识（见 5.3 命名规范）。

P0-1 教师班级归属为空，三块学情看板恒空 P0批次 2/3

现象　教师 tzt001 登录后，首页"班级学情"、成绩页"班级分布"、任务页"本班完成率"三块区域全部为 0，但接口都返回 200、无任何报错。

复现　GET /api/auth/platform-progress → {"scope":"class","class_id":"","total":0,"items":[]}； GET /api/auth/class-students → total=0 class_id=''； GET /api/chain/tutorial/progress/class → class_id="0", total=0（同一个教师，两个入口一个空串一个 "0"）。

根因　直接原因即 P0-4：花名册写库每次必抛异常、又被 except Exception: pass 吞掉，user_info 全库 0 行——看板不是筛不到人，而是连人都不存在（异常原文与行号见 P0-4）。次因：SSO 对教师不返 classId，auth.py:57 把缺失值落成空串，而三块看板都以 WHERE role_id=4 AND class_id=? 过滤，两种情况都是 0 行。

影响　教师最核心的"看本班"能力完全不可用；更糟的是"空"在界面上等同于"你们班没人做"，会被讲成错误结论。

短期绕过　教师手册 3.2 / 7.1 已改为：用成绩册 + 班级筛选器人工核对，三块看板课上不展示。

长期修复　① 教师账号必须有班级：SSO 无班级时由管理员在平台绑定，登录响应加 class_unbound: true； ② 拆掉 _upsert_user_info 的宽泛 try/except，失败写审计日志并在 /auth/session 暴露； ③ scope 缺失时看板显示"未绑定班级 · 去绑定"而不是 0。验收　未绑定班级时三块看板显示引导文案；绑定后 total>0；新增 tests/test_auth_class_scope.py。

P0-4 花名册从未落库：登录写库异常被静默吞掉 P0批次 2

现象　用 tzs001 / tzt001 反复登录，接口全部 200、界面毫无提示，但 user_info 表始终 0 行——而它是全平台唯一的"谁在哪个班"来源。

复现　① POST /api/auth/login → 200；② SELECT COUNT(*) FROM user_info → 0；③ 在库副本上直接调用 _upsert_user_info(data)，即可拿到被吞掉的原始异常 sqlite3.OperationalError: 17 values for 16 columns。

根因　auth.py:89-103：列清单 16 项、VALUES 写了 17 项（login_count 既在列清单里又以字面量 1 占位）、实参只有 15 个；异常被 auth.py:274-277 整体吞掉。UPDATE 分支（auth.py:74）因为永远没有首行而从未被执行。

影响　四条下游链一次全断：① /auth/class-students（auth.py:373 直接读该表）恒空 → 教师看不到本班（P0-1）；② _auto_draft_grade() 取不到真实学号，只能用 W{wallet[:10]} 造主键 → 成绩册里的 W0xlearner、Wstu:0ae778（P0-2）；③ 成就榜 join 不到姓名，只能显示裸 UUID（P3-23）；④ 它恰好是目前唯一挡住 P1-25 引爆的因素。

短期绕过　不依赖花名册：教师以成绩册里手填的姓名 / 班级为准（师 3.2、5.3），班级名单用线下名册核对。切勿为了看板好看手工往 user_info 塞数据——那会立即触发 P1-25。

长期修复　① 对齐列数 / 占位符 / 实参（三处必须一致，建议改命名字段绑定 VALUES(:user_id, …) 防复发）；② 删掉宽泛 except: pass，失败写审计日志并在 /auth/session 暴露 roster_persist_failed；③ 修复后一次性回填历史用户（脚本带干跑模式）。验收　任一角色登录后 user_info 有且仅有 1 行、login_count 随登录递增；且必须晚于 P1-8 / P1-25 上线（见 4.2）。
